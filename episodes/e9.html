۱. نکات طلایی DNS

قانون Same as parent در رکورد MX و A

برای هدایت صحیح ترافیک اصلی دامین (مثل دریافت ایمیل‌ها روی خودِ نام دامین، یا باز شدن سایت بدون پیشوند www)، باید فیلد Name در رکورد خالی بماند.

جزئیات رکوردها

  • رکورد MX (Mail Exchanger): وقتی کسی به user@shoma.com ایمیل می‌زند، DNS مستقیماً روی دامین اصلی دنبال رکورد MX می‌گردد. اگر نام رکورد را مثلاً mail بگذارید، رکورد شما در مسیر mail.shoma.com ثبت می‌شود و ایمیل‌ها به مقصد نمی‌رسند. بنابراین فیلد Name باید کاملاً خالی (Same as parent) باشد.
  • رکورد A برای دامین Flat: اگر بخواهیم کاربران با تایپ gam.net (بدون www) وارد سایت شوند، دقیقاً به همین روش یک رکورد A با نامِ خالی ایجاد می‌کنیم تا مستقیماً به آی‌پی وب‌سرور اشاره کند.

Command مهندسی معکوس با NSLOOKUP

در محیط خط فرمان (CMD)، با اجرای دستور nslookup وارد ابزار می‌شویم. برای فیلتر کردن رکوردهای خاص از دستور set type استفاده می‌کنیم:

> set q=mx
> google.com
Server: UnKnown
Address: 192.168.1.1

Non-authoritative answer:
google.com MX preference = 10, mail exchanger = smtp.google.com

نکته: با زدن set q=ns می‌توانیم رکوردهای Name Server را ببینیم، و با set q=any تمام رکوردهای قابل نمایشِ دامین را استخراج کنیم.

کالبدشکافی مفاهیم پیشرفته DNS

Conditional Forwarder

یک مسیردهی استاتیک است. به سرور می‌گوییم "اگر کسی آدرس دامین X را خواست، درخواست را به آی‌پی Y بفرست".
عیب: اگر آی‌پی سرور دامین X تغییر کند، باید به صورت دستی در شبکه خودمان آن را آپدیت کنیم.

Stub Zone

یک کپی داینامیک و Read-Only از یک زون است که فقط ۳ رکورد حیاتی (SOA, NS, A) را در خود نگه می‌دارد.
مزیت: اگر آی‌پی سرورهای مقصد تغییر کند، به صورت اتوماتیک آپدیت می‌شود و ارتباط قطع نمی‌شود.

تفویض اختیار (DNS Delegation)

دقیقاً مثل سپردن مدیریت یک شعبه به مدیری جدید است. وقتی یک Subdomain (مثل tehran.shoma.com) ایجاد می‌کنیم، به جای اینکه سرور مرکزی مدیریت آن را به دوش بکشد، یک سرور DNS در تهران می‌گذاریم و دامین tehran را به آن Delegate (تفویض) می‌کنیم. با این کار یک رکورد NS در سرور اصلی ساخته می‌شود که درخواست‌ها را به سرور تهران هدایت می‌کند.

پروتکل DNSSEC (به زبان ساده)

مشکل: هکرها با تکنیک Cache Poisoning (مسموم‌سازی کش)، آی‌پی سایت جعلیِ خود را به جای سایت اصلی (مثل بانک) به سرور DNS شما می‌فرستند.

راه‌حل: DNS Security Extensions. این پروتکل پاسخ‌های DNS را رمزنگاری (مخفی) نمی‌کند، بلکه روی آن‌ها یک امضای دیجیتال (مُهر و موم رمزنگاری شده) می‌زند. وقتی کلاینت پاسخ را دریافت می‌کند، امضا را بررسی می‌کند؛ اگر مهر و موم دست‌نخورده باشد، یعنی جواب مستقیماً از سرور اصلی آمده و در طول مسیر توسط هکر دستکاری نشده است.

مدیریت متمرکز پرینترها (Print Server)

انتقال از سیستم سنتی اشتراک‌گذاری به زیرساختِ متمرکز، امن و قابل مانیتورینگِ چاپ در سازمان‌ها.

روش‌های اشتراک‌گذاری پرینتر

  • Traditional Sharing (سنتی): پرینتر با کابل USB به کامپیوتر یک کاربر متصل شده و در شبکه Share می‌شود. مشکل اساسی: ویندوزهای کلاینت دارای محدودیتی به نام SMB Connection Limit هستند و هم‌زمان بیشتر از ۲۰ نفر نمی‌توانند به آن متصل شوند.
  • Print Server Role: با نصب این رول روی ویندوز سرور، محدودیت تعداد کاربران برداشته می‌شود و ادمین می‌تواند تمام صف‌های چاپ (Queues)، درایورها و پرمیشن‌های پرینترهای سازمان را از یک نقطه مدیریت کند.
Network Printer

پرینترهایی که کارت شبکه داخلی دارند و با اتصال مستقیم به کابل LAN، آی‌پی می‌گیرند و وارد شبکه می‌شوند.

Print Server Device

یک قطعه سخت‌افزاری کوچک برای پرینترهای قدیمی. یک سمت آن USB (به پرینتر) و سمت دیگر آن کابل LAN (به شبکه) می‌خورد تا پرینتر قدیمی را تحت شبکه کند.

مدیریت پیشرفته چاپ

نرم‌افزار PaperCut

یک نرم‌افزار قدرتمند جانبی برای مدیریت پرینت. امکاناتی نظیر: تعیین سهمیه برای هر کاربر (مثلاً ۱۰۰ برگ در ماه)، مانیتورینگ دقیق گزارشات چاپ، و قابلیت Find-Me (کاربر پرینت را می‌فرستد، سپس پای هر پرینتری در طبقات کارت بکشد، همانجا برگه چاپ می‌شود) را فراهم می‌کند.

نصب خودکار پرینتر با GPO

برای اینکه پرینترها بدون نیاز به دسترسی ادمین روی سیستم کاربران نصب شوند، از بخش قدرتمند GPO Preferences استفاده می‌کنیم.

User Configuration > Preferences > Control Panel Settings > Printers

با اضافه کردن پرینترِ شیرشده در این بخش، به محض لاگین کردن کاربر در دامین، پرینتر به صورت خودکار به لیست ویندوز او اضافه می‌شود.
